# bookmark-s

一个可以自己部署的书签导航站，用文件夹、标签、搜索和点击热度整理常用网站。页面铺满浏览器，书签列数随可用宽度自动调整，手机上使用抽屉导航；游客可以浏览、访问和推荐网站，登录用户可以收藏个人书签，管理员负责维护公共书签。

![bookmark-s 桌面预览](docs/preview.png)

## 已实现

- **文件夹 + 标签双索引**：每个书签可同时归入多个文件夹，并添加多个标签；文件夹、标签和关键词可以组合筛选。
- 标签支持「全部匹配」（同时包含所选标签）和「任一匹配」（包含其中任一标签）；可查找标签、移除筛选条件，或单独查看「未打标签」的书签。
- 搜索覆盖网站名称、网址、介绍、文件夹名称、标签、添加者和编辑者；每页可选 20 / 50 / 100 个匹配结果，通过底部页码切换，搜索和筛选始终覆盖全部书签。
- 默认置顶书签优先，其余按累计点击量降序排列；也可切换最近添加。各文件夹的置顶分别保存，「全部书签」的置顶也独立保存。
- **个人书签**：登录后点击卡片上的星形按钮（Star）即可收藏，再次点击取消；侧栏「个人书签」只显示当前账号的收藏，访客没有此入口和按钮。
- 点击书签会记录访问次数，数据保存在数据库中。
- 管理员登录后添加、编辑、删除和置顶书签，创建文件夹；在表单中选取已有标签或输入新标签。
- 新建和编辑文件夹提供 108 个图标、6 个主题分类，支持中英文关键词搜索、图标与颜色预览；侧栏使用所选图标和颜色。管理员可修改已有文件夹的名称、图标、颜色，或在保留书签的前提下删除文件夹。
- 管理员、用户、访客三级权限。管理员通过独立的「用户管理」页面创建、搜索、筛选和删除账号，调整角色或重置密码；用户添加的书签自动标注 `@用户名`。
- 站点可设为公开或私人：公开允许访客浏览，私人仅允许已登录的用户和管理员查看内容。「站点配置」中的两个开关统一控制普通用户能否添加、置顶书签。
- 管理员可批量添加、移除标签，也可创建、重命名、删除标签；删除标签会保留网站。
- 游客提交网站推荐时也可以填写标签，管理员在收件箱查看并处理推荐；通过审核后才公开展示推荐及其标签。
- 管理员可在「操作记录」查看所有用户的书签变更、对比修改前后内容，并在没有冲突时回退。
- 每个登录用户都有「个性化配置」：修改自己的密码，或屏蔽指定标签，仅隐藏自己的浏览结果。
- 编辑他人的书签会自动追加编辑者署名，姓名过多时折叠为「+」。
- 内置示例文件夹、书签与标签，首次运行即可体验。
- 一套前端与 API，支持 **VPS + SQLite** 和 **Cloudflare Workers + D1**。

适合个人或小团队共用的书签站；点击量统计的是本站链接的点击次数，不是去重访客数。

## 本地快速体验

需要 **Node.js 24** 和 npm。项目使用 Node 内置 SQLite，无需单独安装数据库。

```bash
npm install
npm run dev
```

打开 **http://localhost:5173**。首次启动会自动创建 `data/bookmark-s.sqlite` 并写入示例数据。内置网站的初始点击数是用于展示排序的演示数据；之后的点击会在此基础上累加，新添加的书签从 0 开始。

开发环境管理员账号：

```text
用户名：admin
密码：bookmark-s-demo
```

开发环境无需配置 `.env`。如果已有 `.env`，其中的账号配置会覆盖默认值；初始管理员通过个性化配置改密后，以数据库保存的新密码为准。前端运行在 5173，API 运行在 8787；Vite 会代理 `/api` 请求。

可以按以下流程验收：打开一个书签并查看点击数变化；使用侧栏的「分享一个好网站」提交推荐（手机上先打开左上角菜单）；登录管理员，在收件箱查看推荐，添加一个书签并置顶；刷新页面或重启服务，确认数据仍在。

## 账号与访问模式

管理员侧栏提供独立的管理页面：

- **站点配置**：选择公开或私人模式；用滑动开关统一设置「允许用户添加书签」和「允许用户置顶书签」。两个开关分别控制所有普通用户，默认关闭；管理员始终拥有完整权限。私人模式的访客只看到登录入口，API 同样不返回书签、标签、文件夹及统计内容。
- **用户管理**：按用户名搜索、按角色筛选，创建账号、调整角色、重置密码或确认删除账号。本站不开放自行注册；新密码至少 10 个字符。重置密码或删除账号后，原有会话失效。删除账号保留它添加过的书签和作者标注，初始管理员及当前登录账号不能删除。
- **操作记录**：查看全部用户的书签变更，按关键词、操作类型和操作人筛选，再查看详情或回退。

普通用户默认可浏览、收藏个人书签和提交待审核的推荐。开启添加开关后可直接添加书签，开启置顶开关后可置顶和取消置顶；这两个开关不影响个人收藏，也不会授予编辑、删除书签、管理文件夹或用户的权限。

新添加的书签由服务端自动绑定登录用户名，卡片优先显示原添加者 `@用户名`，之后追加实际编辑过内容的其他用户，重复编辑不会重复署名；置顶和点击不会追加编辑者。放不下的署名折叠为「+」，悬停可查看完整名单。环境变量配置的初始管理员显示在用户管理中，角色固定，用户名继续通过服务器配置维护；密码可在自己的个性化配置中修改。其他账号、站点模式和统一权限保存在数据库中，重启后保留。权限变更在后续 API 请求中生效；浏览器回到页面或刷新后会同步更新操作入口。

每页数量位于「最受欢迎 / 最近添加」左侧，默认 50 个，可选 20 / 50 / 100 个。底部支持页码、上一页、下一页和指定页码跳转；跳转只接受有效范围内的整数。改变筛选、排序或每页数量会回到第 1 页。未打标签的书签显示带感叹号的黄色提示标签。

页面、文件夹、关键词、标签匹配条件、排序和分页状态会保存在地址栏中。刷新页面、复制链接，或使用浏览器前进/后退，都能恢复对应的浏览位置；连续输入搜索词不会逐字增加历史记录。每页数量会记住为当前浏览器的偏好，链接中指定的数量优先；浏览器禁用本地存储时仍可正常使用。取得内容后会自动移除失效的文件夹和标签，并将超出范围的页码调整到有效范围；私人站点的链接会保留筛选，登录后再恢复内容，管理页面链接仍遵守账号权限。

## 个人书签

登录后，书签卡片上会出现星形按钮（Star）。点击后星形点亮，书签加入侧栏「个人书签」；再次点击取消收藏，在个人书签页取消后会立即移出列表。个人书签支持关键词、标签、排序和分页，刷新或重新登录后仍然保留，也会在同一账号的其他设备登录后显示。

收藏按账号保存在服务器中，管理员和普通用户各有自己的列表；访客看不到个人入口或按钮，也不能调用收藏接口。收藏不会修改公共书签的内容、全局或文件夹置顶、点击数、添加者或编辑者，不会写入公共操作记录。原「置顶收藏」入口已替换为「个人书签」，现有置顶保持原样，不会自动转成任何账号的个人收藏。

屏蔽标签时，相关个人书签会暂时隐藏，取消屏蔽即可恢复。编辑书签、调整标签和文件夹、回退这些修改都保留当前收藏；真正删除书签会清除所有账号对它的收藏，之后回退删除也不会恢复历史收藏。删除账号只清除该账号的个人收藏，不影响其他用户。

## 操作记录与回退

操作记录从本次升级后开始保存，已有书签不会生成虚构的历史。新增、编辑、删除、全局或文件夹置顶、批量标签调整、标签重命名/删除、文件夹编辑/删除、审核收藏均会留痕；失败请求和没有实际变化的保存不会新增记录。访问网站继续累计点击数，不作为内容变更记录。每次批量操作显示为一条记录，可展开查看涉及的每个书签。

管理员可从「操作记录」按书签标题、网址、操作人和操作类型查找记录，查看修改前后的具体差异，再点击「回退此操作」并确认。该页面不受管理员个人屏蔽标签的影响；普通用户和访客无法读取日志或执行回退。操作人的署名及变更快照会随数据库保留，删除账号或书签也不会删除已有日志。

回退会恢复操作前的内容、文件夹归属、各处置顶和署名；恢复被删书签时保留原身份及点击数，回退其他编辑时保留之后新增的点击。回退审核收藏会将推荐重新放回待审核状态。回退新增则移除该次创建的书签。

提交回退时会再次检查当前内容、标签关联与网址等依赖。若发生后续修改或依赖冲突，会拒绝覆盖并说明原因；可以先处理较新的记录，再逐步回退。批量回退要么全部成功，要么保持原状。回退本身会生成新日志，原记录标记为已回退，不能重复执行。

## 个性化配置

所有登录用户（包括初始管理员）都可以从侧栏进入「个性化配置」：

- **屏蔽标签**：搜索并勾选标签，保存后，带有任意一个屏蔽标签的书签会从自己的列表、搜索、推荐展示和点击统计中隐藏。其他用户及访客不受影响。已屏蔽标签仍可在个人设置中找到，取消勾选并保存即可恢复显示；不会删除书签。
- **修改密码**：填写当前密码、新密码和确认新密码，新密码至少 10 个字符。修改成功后所有旧登录会失效，需要重新登录。初始管理员改密后，新密码持久化在数据库中并优先于 `ADMIN_PASSWORD`；重启不会恢复旧密码。

## 编辑和删除文件夹

管理员可点击侧栏文件夹旁的铅笔或删除按钮。普通用户和访客没有这些入口，相关 API 也只允许管理员调用。

编辑可修改名称、图标和颜色，不改变文件夹身份、书签归属或置顶。原有自定义颜色会保留，直到主动选择新颜色。

删除前会显示完整影响范围，包括被管理员个人设置隐藏的书签和所有网站推荐：

- 同时属于其他文件夹的书签，只移除待删文件夹这一项归属，保留其他文件夹的置顶状态。
- 只属于待删文件夹的书签和推荐，必须迁移到所选的另一文件夹；迁移保留书签点击数、署名和全局置顶，原文件夹的局部置顶会带到新位置。
- 删除最后一个仍有内容的文件夹前，需先新建一个迁移目标；空文件夹可以直接删除。

提交删除时服务器会重新校验目标和影响范围，避免预览之后的新内容变成无归属。文件夹编辑、删除和迁移会一起记入操作记录；没有后续冲突时，可回退恢复文件夹及原有归属。

## 用文件夹和标签整理收藏

新建文件夹时，可从图标库选择合适的图形。输入「音乐」或 `music` 等关键词搜索，也可以按主题筛选；搜索和切换主题不会丢失已选图标。预览会随文件夹颜色更新，创建后在侧栏显示，已有文件夹图标保持兼容。

文件夹适合表达主要归属，例如「开发工具」「阅读学习」；标签适合表达跨文件夹的用途或特点，例如「免费」「开源」「前端」「稍后阅读」。添加、编辑或推荐网站时，可以同时勾选多个文件夹，至少选择一个；同一网址仍只保存一份书签，标题、介绍、标签和点击数在不同文件夹中共享，也可以同时标记「免费」「开源」「前端」。每个书签最多 12 个标签，每个标签最多 24 个字符，重复名称会自动合并。

每个文件夹单独保存书签的置顶状态。在「开发工具」置顶不会改变「阅读学习」的状态；在「全部书签」中的置顶也单独保存，影响公共列表的排序。编辑归属时，保留下来的文件夹继续保留原置顶状态，新增文件夹默认不置顶。个人收藏由星形按钮独立控制。

先点侧栏文件夹缩小范围，再选标签继续筛选。例如选中「开发工具」，再选「免费」和「前端」，默认的「全部匹配」只显示同时符合这两个标签的网站；切换「任一匹配」会显示符合任意一个标签的网站，范围仍受当前文件夹限制。关键词可以继续缩小结果，也可以直接搜索标签名。标签旁的数量会随当前筛选变化，数量为 0 的标签不会出现在可选列表中；标签搜索和「更多标签」也只在当前范围内查找。已选标签即使没有匹配结果，仍可在筛选条件栏中取消。

登录后，添加或编辑书签时可点击已有标签，也可输入新名称并按 Enter 或逗号添加；直接保存也会收录尚未提交的标签输入。大量旧书签可以先筛选「未打标签」，点「批量整理」，勾选当前页的网站后添加标签。「选择当前页」只选择当前页卡片。批量添加保留原有标签，批量移除只移除指定标签。翻页、改变每页数量、排序或切换文件夹、标签、关键词会清空勾选，避免误改隐藏的网站。

「管理标签」可以统一修改标签名称，相关书签会同步更新；删除标签只解除标签关联，文件夹、网站、点击数和置顶状态都会保留。

### 从旧版本升级

Node / Docker 在启动时自动执行增量迁移，保留已有书签、文件夹、点击数和置顶状态。多文件夹升级会将原归属及置顶迁入文件夹关系，同时保留「全部书签」的原置顶；已有署名不会被改写。已有书签不会被补写虚构的添加者，现有访问模式保持不变。升级后旧的单独用户授权不再生效，请在站点配置中按需开启统一权限；两个新开关默认关闭。原有分类会直接作为文件夹继续使用。内置示例网站会获得演示标签，自行收藏的网站保留为空标签，方便逐步整理；后续启动不会覆盖已经编辑的标签。

Cloudflare D1 需要先应用尚未执行的迁移（含 `0002_tags.sql`、`0003_accounts.sql`、`0004_site_permissions.sql`、`0005_collections_preferences.sql`、`0006_operations.sql`、`0007_category_operations.sql` 和 `0008_personal_favorites.sql`），再部署新版：

```bash
npm run cf:db:migrate
npm run cf:deploy
```

本地 Worker 使用 `npm run cf:db:migrate:local`。迁移不需要删除或重建数据库。

## VPS 部署

### 使用 Docker Compose

先复制配置文件，并把 `ADMIN_PASSWORD` 和 `SESSION_SECRET` 改为你自己的值：

```bash
cp .env.example .env
# 生成 SESSION_SECRET，再把输出填写到 .env
openssl rand -hex 32
```

`ADMIN_PASSWORD` 至少 10 个字符，`SESSION_SECRET` 至少 32 个字符。随后运行：

```bash
docker compose up -d --build
docker compose logs -f app
```

服务监听 **http://127.0.0.1:8787**，数据库保存在 Docker 命名卷中。将域名通过 Caddy 或 Nginx 反向代理到这个地址，并配置 HTTPS。在 `.env` 中设置 `PUBLIC_URL=https://bookmarks.example.com`（替换为你的域名，不含路径），再执行 `docker compose up -d`，让 API 正确校验浏览器请求的来源。例如 Caddy：

```caddyfile
bookmarks.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

反向代理部署还需在 `.env` 中配置 `TRUSTED_PROXIES`，填写明确受信任的各级代理 IP 或 CIDR，包括 API 实际连接到的代理。直接在同机运行 Node + Caddy/Nginx 时通常是 `TRUSTED_PROXIES=127.0.0.1/32,::1/128`；Docker 中的对端通常是容器网关或代理容器地址，需要按实际网络配置填写，不能直接套用宿主机回环地址。Compose 已通过 `env_file` 传入此配置，无需修改 Compose 文件。Caddy 默认传递客户端地址；Nginx 对应配置为 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`。

`TRUSTED_PROXIES` 默认空。API 只有在 socket 对端可信时，才从 `X-Forwarded-For` 右侧逐跳检查已知代理，遇到第一个不可信地址即停止；缺失或畸形的头会退回 socket 地址。只将自己管理的代理列入名单，不要配置全网范围。Cloudflare Workers 使用平台提供的 `CF-Connecting-IP`，不使用这项 Node 配置。

生产环境的登录 Cookie 默认只通过 HTTPS 发送。如果只是本机通过 HTTP 验证 Docker，在 `.env` 中临时添加 `SECURE_COOKIES=false`，然后重新执行 `docker compose up -d`。正式 HTTPS 部署时删除该配置。

更新代码后再次运行 `docker compose up -d --build` 即可；不要用 `docker compose down -v`，它会删除数据库卷。

### 直接使用 Node.js

准备好上述 `.env` 后执行：

```bash
npm ci
npm run build
npm start
```

`npm start` 以生产模式运行，同时提供构建后的网页与 API，默认端口 8787。可用 systemd 或你熟悉的进程管理器保持运行，并按上面的方式配置 HTTPS 反向代理。

## Cloudflare 部署

Cloudflare 方案使用 **Workers 静态资源 + Worker API + D1 数据库**，不依赖 VPS，也不是仅上传静态文件到 Pages。

### 先在本机测试 Worker

```bash
npm install
cp .env.example .dev.vars
# 编辑 .dev.vars，设置 ADMIN_PASSWORD 和 SESSION_SECRET
npx wrangler d1 migrations apply bookmark-s --local
npm run cf:dev
```

打开 Wrangler 输出的本地地址。这里使用独立的本地 D1 数据库，与 Node 的 `data/` 互不共享。`.dev.vars` 中的账号会用于登录。`wrangler.jsonc` 的占位数据库 ID 可用于本地测试。

### 部署到 Cloudflare

```bash
npx wrangler login
npm run cf:db:create
```

将命令返回的 **`database_id`** 填入 `wrangler.jsonc`，替换全零占位值。`database_name` 保持 `bookmark-s`。然后运行：

```bash
npm run cf:db:migrate
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put SESSION_SECRET
npm run cf:deploy
```

两个 `secret put` 命令会分别提示输入密码和随机密钥；长度要求与 VPS 相同。用户名默认 `admin`，可在 `wrangler.jsonc` 的 `vars.ADMIN_USERNAME` 中修改。`.dev.vars` 只服务本地开发，不会替你配置线上密钥。

首次 D1 迁移会创建表并写入示例数据。部署命令自动构建前端，成功后访问 Wrangler 返回的 Workers 地址，也可以在 Cloudflare 控制台绑定自己的域名。后续有新迁移时，先运行 `npm run cf:db:migrate`，再部署。

## 配置与数据

| 配置 | 默认值 / 要求 |
| --- | --- |
| `ADMIN_USERNAME` | `admin` |
| `ADMIN_PASSWORD` | 开发模式默认 `bookmark-s-demo`；生产 / Worker 必填，至少 10 个字符 |
| `SESSION_SECRET` | Node 开发模式内置；生产 / Worker 必填，至少 32 个字符 |
| `HOST` | Node 默认 `0.0.0.0` |
| `PORT` | Node 默认 `8787` |
| `DB_PATH` | Node 默认 `data/bookmark-s.sqlite` |
| `SECURE_COOKIES` | Node 生产模式默认开启；本机 HTTP 测试可设为 `false` |
| `PUBLIC_URL` | HTTPS 反向代理部署时填写公开站点来源，如 `https://bookmarks.example.com`，不含路径 |
| `TRUSTED_PROXIES` | Node / Docker 默认空；可信代理的 IP/CIDR，逗号分隔；用于安全解析真实客户端 IP |

Node 会自动加载项目根目录的 `.env`。Cloudflare 本地读取 `.dev.vars`，线上通过 Wrangler secrets 和 bindings 配置。修改管理员密码或会话密钥后重启 / 重新部署服务；修改会话密钥会使已有登录失效。

### 访客识别与限流

站点使用一个服务器签名的随机浏览器标识 Cookie（`bookmark_s_visitor`，有效期 180 天）区分匿名访客；它是 HttpOnly Cookie，不采集设备指纹，也不读取网页无法获取的 MAC 地址。成功登录后，投稿按服务器验证的账号 ID 计数，因此同一账号更换浏览器仍共享个人配额。

| 操作 | 个人配额 | 同一真实 IP 的总量上限 |
| --- | --- | --- |
| 登录 | 每个浏览器、每组“账号 + IP”分别最多 12 次失败 / 15 分钟；成功登录释放个人配额 | 120 次尝试 / 15 分钟 |
| 投稿 | 匿名浏览器或已登录账号各 5 次 / 小时 | 60 次 / 小时 |

登录在异步校验密码之前预占配额，避免并发请求突破限制。删除、篡改或轮换浏览器 Cookie 仍受 IP 总量上限约束；不同账号和不同匿名浏览器在同一网络下有各自的个人配额。达到限制时 API 返回 `429` 和 `Retry-After` 秒数。登录后的身份只取签名会话及当前账号状态，不接受请求正文声明的用户身份。

计数保存在当前 Node 进程或 Worker isolate 的内存中，重启会清空；多实例部署如需全局共享限流，应在网关配置统一策略。

**备份：**直接运行 Node 时，先停止进程，再备份整个 `data/` 目录。Docker 可以短暂停机后复制数据目录：

```bash
docker compose stop app
docker compose cp app:/app/data ./backups
docker compose start app
```

Cloudflare D1 可导出为 SQL：

```bash
npx wrangler d1 export bookmark-s --remote --output=bookmark-s-backup.sql
```

备份文件包含站点数据，请放在仓库之外妥善保存。首次初始化后不会因重启重新插入示例书签；运行时数据与代码分离。

## 开发

```bash
npm run typecheck
npm test
npm run build
```

浏览器端到端测试覆盖访客搜索与点击、推荐审核、管理员书签管理、手机端菜单、个人收藏与账号隔离，以及文件夹与标签交叉筛选、全部 / 任一匹配、标签编辑持久化、批量整理、标签重命名 / 删除和 600 个书签的渐进显示与全量搜索。测试使用独立的临时数据库，不会读写 `data/` 中的收藏：

```bash
npx playwright install --with-deps chromium
npm run test:e2e
```

| 路径 | 用途 |
| --- | --- |
| `src/` | React 前端与样式 |
| `server/` | 共享 Hono API、Node 服务和 API 测试 |
| `worker/` | Cloudflare Worker 入口 |
| `migrations/` | 数据库表结构和初始数据 |
| `wrangler.jsonc` | Cloudflare Workers 与 D1 配置 |
| `compose.yaml` / `Dockerfile` | VPS 容器部署 |

`GET /api/health` 可用于检查服务是否存活。开发 API 与前端通过 Vite 代理保持同源；生产由同一服务提供，管理员会话使用 HttpOnly Cookie。
